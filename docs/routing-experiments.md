# A*와 CCH·LPA* 추가 비교 실험

기준: GitHub main `0b4a198064ce2f1428388a546909b886c231f53c`.
작업 브랜치: `NamGyu-Final`.

기존 페이지, CSS, 지도 데이터, 알고리즘 구현은 유지한다. `/study`에 두 탭만 추가하고,
기존 `SearchCanvas`, `AlgoHeading`, `LogChart`, 색상 토큰과 카드·표 스타일을 사용한다.

## 1. A* ↔ CCH: 여러 요청

- 같은 크기의 조치원 지도에 서로 다른 출발·도착 요청 1/10/100/1,000개를 생성한다.
- 첫 요청만 기존 시뮬레이션에서 선택하고 나머지는 고정 시드로 생성한다. 요청 수를 늘려도 앞쪽 요청은 유지된다.
- 정상, 혼잡 또는 폐쇄 상황 하나를 모든 요청에 공유한다. 변경 도로는 전체의 1% 또는 10%다.
- A*는 매 요청 새로 계산한다. CCH는 구조 전처리·정상 비용 준비·교통 정보 반영을 각각 한 번 수행한 뒤 모든 요청에 재사용한다.
- 누적 시간은 실제 요청들의 계산 시간을 합산한 값이다. 한 요청의 시간에 요청 수를 곱한 추정값이 아니다.
- 기본은 첫 준비 비용 포함. 제외 시에도 이번 교통 정보 반영 비용은 포함한다.
- 여러 요청 중 첫째·가운데·마지막 요청의 탐색 기록을 재생한다.

## 2. A* ↔ LPA*: 연속 변화

- 같은 출발·도착에서 정상 계획 후 혼잡→폐쇄→해소를 9/30/60회 적용한다.
- 국소 변화는 정상 경로의 도착지 쪽 1/3 안의 도로 하나, 광범위 변화는 전체 도로의 10%다.
- A*는 매 변화 처음부터 탐색한다. LPA*는 첫 계획과 매 변화 사이의 상태를 계속 유지한다.
- 매 변화의 응답 비용에 LPA*의 `setWeight()`와 `compute()`를 모두 포함한다.
- 정상 상태 첫 계획을 포함한 누적 시간과, 준비 완료 이후 누적 시간을 함께 제공한다.
- 각 변화의 탐색 기록·이전 경로·혼잡·폐쇄 도로를 기존 지도 화면에서 재생한다.

## 공통 검증·측정

- 목표 비용은 추정 이동시간(초)이다. 정상 속도 30km/h, 혼잡 ×4, 폐쇄 Infinity.
- 길이는 별도 출력한다. 최소 이동시간이 항상 최단거리를 뜻하지는 않는다.
- 정답은 각 요청/변화에 대해 다익스트라로 먼저 구한다. 모든 측정 응답에서 상태·최소 비용·경로 연결·일방통행·폐쇄 통과 여부를 검사한다.
- 워밍업 1회 후 5회 측정하고 반복마다 두 알고리즘의 실행 순서를 교대한다.
- 각 반복의 실제 누적 합을 구한 후 중간값을 낸다. 개별 응답 중간값의 합으로 대체하지 않는다.
- 정답 검사와 재생 기록 생성은 측정 구간 밖이다. 화면은 Worker로 실행하고 중단할 수 있다.
- 재생 기록은 별도 실행에서 생성한다. 재생 속도는 측정 시간과 무관하다.
- 브라우저 타이머가 0ms로 반환한 응답은 ‘측정 해상도 미만’으로 표시한다. 로그 그래프에서는 0인 점을 생략한다.
- 유리한 결과를 강제하지 않는다. A*가 더 빠른 결과도 그대로 표시한다.
- 실험은 이 구현과 지도, 브라우저·기기의 결과다. 산업 서비스의 성능을 대신 측정하지 않는다.
- CCH의 저장 공간과 LPA*의 이전 상태 저장은 설명하지만 메모리 사용량을 실제 측정하지는 않는다.
